# Runtime architecture

`game/main.js` starts `app/bootstrap.js`. Application assembly owns shared services; world controllers own their scene, collisions, puzzles, story and rendering.

| Module                  | Responsibility                                                   |
| ----------------------- | ---------------------------------------------------------------- |
| `app/bootstrap.js`      | Construct services, load the character, assemble the application |
| `app/campaign.js`       | Chapters, progress, world transitions and the finale             |
| `app/ui.js`             | Loading, menus, settings, notes and pointer capture              |
| `carousel.js`           | One card centre stage, turned by keys, arrows, swipes and clicks |
| `level-select.js`       | The levels screen's world cards and starts on a carousel         |
| `app/loop.js`           | Input, physics, animation, camera and frame order                |
| `app/rendering.js`      | Renderer setup, shader preparation and resizing                  |
| `app/diagnostics.js`    | Browser telemetry used by verification scripts                   |
| `worlds/catalog.js`     | Ordered world definitions and derived chapter/lab entries        |
| `worlds/manager.js`     | Loading, lifecycle dispatch, portal connections and cached state |
| `worlds/work-budget.js` | Cooperative background construction and foreground promotion     |
| `app/shader-preview.js` | Independent character copy for neighboring shader preparation    |
| `asset-catalog.js`      | Factory metadata and runtime aliases                             |
| `asset-store.js`        | Requested factory loading, availability and prototype reuse      |
| `asset-finish.js`       | Shared fitted material detail in the game and lab                |
| `offload.js`            | Worker pool for factories and pixel loops, with exact fallbacks  |
| `fit-cache.js`          | Replayed garment fit for the explorer                            |
| `worlds/gpu-budget.js`  | Residency tier from the device's estimated graphics memory       |
| `tree-lod.js`           | Distance levels for the Wildwood's tree batches                  |
| `early-world-detail.js` | Grounded environmental detail with unchanged traversal shapes    |
| `weapon-reload.js`      | Magazine exchange timing and pooled falling magazines            |
| `atmosphere.js`         | Per world grade and atmosphere, and Nyra's close-up lighting     |
| `relic-showcase.js`     | The Relics screens' stage, drawn in place of the world           |
| `relic-figures.js`      | Pages and the builders' stone for relics that are records        |

## Worlds and loading

`WORLDS` determines chapter order and both portal neighbors. Public chapter identifiers and `far-door-` save keys stay stable; internal world identifiers retain their existing values. `CHAPTERS` and `LAB_LEVELS` derive from these definitions.

Controllers live in `worlds/{court,checkpoint,isles,frost,forest,sea,vault}/index.js`. The root `world-*.js` modules retain their named exports. Geometry, physics and scenery helpers remain shared game modules.

A definition with `entry: "finale"` is reached from its predecessor's finale rather than through that world's exit door: `WorldManager.doorTo` neither points the exit at it nor crosses into it, while `neighbors` still prepares it beside its predecessor. The builders' vault is such a world, after the drowned archive. `campaign.finale` asks `WorldManager.finaleTo` whether a finale leads on: the space crossing's shot then keeps its closing card down (`start(..., { onward })`) and, when it ends or is skipped, crosses into the vault with `{ arrive: true }`; only the last world's finale calls `finishGame` and rolls the credits.

Progress keeps the `far-door-progress` format. `completed` with `campaign` 6 or more reads as a finished campaign; any older completed save reads as the four-level one and opens the forest. `campaign` records where the finish was earned: 6 at the drowned archive (saves from before the vault), 7 in the vault, which `finish` now writes. A finished campaign adds `vault` to `reached`, both at load and in `finish`, so the vault's chapter opens without a new field, and the levels screen marks completion on the archive for campaign 6 and on the vault for campaign 7.

`ensure(id)` runs one preparation at a time and deduplicates requests. A waiting foreground request runs next, and the running background job stops yielding so it finishes quickly. Newly wired controllers reset before shader preparation, so the first entry uses the same puzzle state as a restarted chapter. `prepare(id)` requests the selected world and its immediate neighbors together, so no queued background world runs between them. A chapter started from the menus waits under its loading screen for that window alone, and the worlds the title has not prepared yet follow in the background during play, held back 2.5 s after the start. A chapter started by address (`?chapter=`) instead finishes every unprepared world under its loading screen (`settle`), so captures and scripted checks never compete with preparation. The title loads the court in the foreground.

While the Relics or relic account screen is open, `loop.js` asks `ui.renderStage(dt)` before drawing the world: once its stage is built, `RelicShowcase` draws its own small scene straight to the screen, restoring the renderer's target, clipping planes and exposure, and the world is not drawn. The stage is imported on first opening, so the title's modules do not include it; the screen owns the chosen relic and the stage reports drags and taps through `onSelect` and `onPick`.

The title's downloads arrive together rather than one round trip at a time. `index.html` lists as module preloads every module the title imports, written by `scripts/boot-preload.mjs`, whose `--check` the architecture check runs. The court's build first preloads the assets it then makes one after another (`AssetStore.preload`); a preload only downloads, so modules still run in the build's order. The levels screen's world pictures (`ui/levels/<world>.webp`) are requested only when that screen opens (`createLevelSelect().refresh`), never on the title's path.

`prefetch(id)` prepares the next and previous worlds at background priority. With `retainAll` it also builds every world not yet built, nearest first; the title screen starts this, so later crossings find their destination ready. Background work yields on a cooperative budget of 12 ms on the title screen and 4 ms in play. Long loops are generators run by `runSteps` (`work-steps.js`), which pauses at each `yield` once the budget is spent: isle cap measurement, the forest and frozen grounds and the render budget's shadow casters use it, and a world's module and constructor run apart from its build. `WorldWorkBudget.hold(ms)` suspends background work during door crossings, chapter starts, cinematics and the finale, while a foreground request still runs at once. If the destination is still pending, the source remains visible and the hero holds position until it is ready. Background failures preserve the playable world and permit retry.

Heavy pure work leaves the main thread through `offload.js`, a pool of two module workers whose jobs never change a result. Workers cannot read the page's import map, so whatever they import loads three.js by its vendored path or not at all. The import-free factories listed in `OFFLOADED_ASSETS` (`asset-store.js`) are built in a worker once the first world after the court starts preparing, so the title's own build keeps the workers for its pixels, and the mountain ridges at startup; `offload-codec.js` carries their trees back as transferable buffers, recreating objects and materials in their original creation order, and refuses textures, shader hooks, lights and skinning, which then build on the main thread. Canopy textures that every thread builds identically travel by name (`shareTextures`). Detail, mineral and canopy maps are `deferPixels` images: a worker computes their pixels, and reading `data` before it answers computes them on the main thread, so a slow or missing worker changes timing only. Preparation waits for outstanding pixels before compiling (`pixelsSettled`), and pixel jobs overtake queued factories. A payload in another `FORMAT`, a worker silent for 8 s or a tree that fails to decode builds on the main thread instead; idle workers close after 20 s, and the worker's address carries the release stamp of `offload.js`. `receipts/verification-zero-hitch/offload-check.mjs` and `detail-equivalence.mjs` compare worker results with main-thread builds and the starting tree, value for value.

`fitSession` in `fit-cache.js` replays the explorer's garment fit: `scripts/build-fit-cache.mjs` records which triangle each of its 22,084 surface rays hits into `assets/explorer/fit-cache.json`, and a replay intersects only that triangle through three's own raycast, so fitted geometry stays bit-identical. Every query is hashed with its ray and its target's contents and checked every 64 rays and at the end; any difference rebuilds the explorer with the live fit, which `fitTelemetry` reports as `stale`. Run the script after changing the explorer's fitting modules or data.

Hardware shader preparation uses an independent character tree and bones that share the explorer's own depth materials; a depth material is never lit, so three.js keeps its first program whatever the lights, and the copy compiles and releases no shadow program. It compiles the scene in groups of about forty drawable objects, uploads textures one at a time, then draws each group once with culling off into the destination's offscreen composer, before the full warm render. A door draws its world into a target with a sample count of its own, and a program's first draw at a new sample count builds a pipeline even when compiled, so the groups draw again, clipped and unclipped, into a 16 px copy of the target of the door that shows the world (`doorStandIn`), unless both counts match; pipelines outlive released targets and uploads, so a restored world skips a pass it already made. Groups are isolated with layers, never visibility, so lights and program keys stay unchanged; static shadow maps are requested before those draws. Render targets and clipping planes restore before each asynchronous shader wait. Software renderers retain their deferred shader warm-up.

`enter(id)` leaves the previous controller, then enters the cached instance. Returns retain solved puzzles. `solveBefore(id)` also marks unloaded predecessors, so loading them later restores the chapter's expected progress. `reset()` resets loaded scenes and clears deferred solutions. Cached scenes remain built for the session.

`residencyPolicy` (`worlds/gpu-budget.js`) picks how many worlds stay uploaded from an estimated graphics budget: a quarter of `navigator.deviceMemory` on a fine pointer, 15% on a coarse one (8 GB and 4 GB when unreported), at most 2 GB of memory when the largest texture is under 8,192 pixels. A world needs about 80 MB of geometry and textures plus 45, 20 or 10 MB of targets in High, Balanced or Fast. `all` (`retainAll`) keeps every world and only shrinks composers and portal targets; it needs a fine pointer, a hardware renderer and room for every world, so ordinary desktops keep it. `neighbors` keeps the active world and both neighbours, the phone path, also used by software renderers. `next` keeps only the active world and the next one: the previous world is neither prefetched nor protected, and a return restores it while the hero holds position. Outside the kept window, geometry, textures, shadow maps and render targets are released. `worlds.telemetry().residency` reports the tier and budget.

The Wildwood's tree batches keep their depth bands. `TreeLevels` (`tree-lod.js`) gives each band a far level: trunks and canopy lobes merge vertices that share a cell of 1/25 of the mesh's height and a facing, and leaf cards keep one card of each crossed pair, about half the triangles. A band switches beyond 115 m from its nearest tree and back within 100 m, only by swapping geometry under the same materials, so programs never change; preparation draws every far level once to upload it.

`object-copy.js` replaces `Object3D.copy`'s JSON round trip of `userData` when it holds scene objects or GPU resources: declared parts map to the clone's own nodes instead of serializing whole subtrees and their geometry on every clone.

A controller exports a default class accepting `(renderer, assets, services)`, implements `build`, `wire`, `enter`, `leave`, `startStory`, `update`, `render`, `renderInto`, `reset`, `solve` and `resize`, and exposes `scene`, `world` and its outgoing `exit`. Portal destinations expose `gateCenter` and `clipPlane`. Hardware-rendered worlds beyond the court implement `prepareForCompile(on)`. Optional `connect`, `returnCrossed` and `combatTargets` hooks handle shared scenery, return gates and weapons; an optional `breath` and `headWater(hero)` feed the breath meter and the underwater sound outside the archive. The final controller supplies its own finale and completion callback; a world whose last door shows another scene exposes it as `epilogue` with that door as `gate`, and the shader preparation compiles it in both the portal and the composer.

The vault (`worlds/vault/index.js`, with `vault*.js` beside it) builds its hall and six trials from the existing systems: the court's `Beams` and mirrors, the Wardens and the relay's shield, the isles' `Bridge`, pylons and a `SwingRope`, frozen-pond sliding with the relay's tether and a scarred fall (`Curtain`), the forest's bog water and ivy (`ivyFaces`), and the archive's swimming, `Breath` and a `CurrentField`. `vault-climbs.js` builds the climbing faces, and entering the vault gives Nyra Mira's axes, the tether and the shield. Each trial wakes a seal; its channel runs to a medallion on the sealed door. With all six lit, the door opens on a `RevealShot` and the next door; crossing it calls `services.onComplete`, which finishes the campaign and plays the vault's `finaleShot` and the credits. Its script is `vault-lines.js`: `onBeat(id)` speaks Mira's lines live through `miraVoice` (clips `game/audio/voice/vault-*.mp3`) and shows Nyra's thoughts as subtitles.

To add a chapter, implement its controller and add its definition to `WORLDS`. Add its factories to `ASSET_CATALOG`, its runtime aliases when required, and its puzzle/scenery modules. Menu entries, lab launch links and sequential portal connections derive from the catalog.

## Controls and options

`input.js` keeps the default `MOVE`, `ACTIONS` and `PAD` tables; `settings.bindings` (store.js) holds only the keys and buttons a player changed, and its absence means the defaults. `Input.binding(action)`, `padButton(action)` and `label(action)` resolve every read, prompt and card, and `remappable()` lists every table entry except `skip`, so an action another module adds is bound, labelled and editable without further wiring. Escape always pauses, Start and Back stay with the menus, and R stays shared between the orb's link and the pistols' reload. `controls-screen.js` edits the bindings: a key taken from another action goes back to it in exchange. `app/ui.js` binds every option row and turns subtitle size and backing, high contrast and reduce motion into body classes; `FollowCamera.settings` carries the field of view and recentering, and `CalmCamera` softens cinematic moves under reduce motion. `setting-controls.js` turns each option select but the language into a cycler that keeps the select as its value store and for screen readers, and `settingChanged` shows every change in its cycler or range, whether a click, a key or a gamepad made it.

## Languages

The game's English text is its translation key: `t(text, values)` (`i18n.js`) returns the entry of the loaded table, or the English when there is none, and fills `{name}` placeholders. `main.js` loads the table before importing `app/bootstrap.js`, so modules translate their constant text as they evaluate, and `translatePage` translates the page's own text: an element marked `data-i18n` is translated whole, one marked `translate="no"` keeps its text. Keys are literal strings at their definition; a value that is already text is never passed to `t()` again. The language comes from a `lang` query, then the saved `language` setting, then the browser's languages; automated browsers keep English so checks read the source text. Settings' language row opens a list of the languages, each written in itself, with Automatic naming the browser's language (`browserLanguage`); a choice that changes the text reloads the page at once, restarting a level in progress from its own start, or from the title coming back on Settings (`far-door-reopen` in session storage, read by `ui.reopenMenu`). Tables live in `i18n/<id>.js`, one per language; Chinese and Hindi glyphs fall back on system faces declared under `:lang()` in `style.css`. Mira speaks every language: `voice.js` loads `audio/voice/<id>/<clip>.mp3` for the chosen language and falls back on the English take, and a scene whose line runs past the room it gives (`Beat`, the reunion, the vault's reveal) slows its clock with `paceFor` until the line ends, so English timing is unchanged. `scripts/i18n-check.mjs --write=<file>` lists every key and fails on a missing, stale or mismatched entry or on a call that a local `t` hides; `--candidates` lists literals that read like prose but are not wrapped. `scripts/i18n-set.mjs <id> '<json>'` adds or replaces a table's entries.

## Light and atmosphere

`atmosphere.js` installs each world's light and atmosphere while the world prepares: `precompile` calls `rendering.lighting.attach(id, world)` before any shader compiles, and the world's `beforeRender` updates it each frame while that world is `app.worlds.current`: a world drawn through a door runs the same hook and must leave the frame's grade and Nyra's light alone. Each composer's output pass carries the world's grade (`grading.js`): an exposure before the tone curve, then lift, gamma, gain, saturation and an S-curve contrast on display values, eased across crossings and neutral while the space finale draws. During play the effects change only light values and uniforms, and no scene gains a light: a world's light count keys its programs, Nyra's depth variants included, so the isles' golden rim lives in her own materials. The court's heat haze (`heat-haze.js`) reads the scene depth from its composer's targets and is off on Fast. The frozen reach's environment map is redrawn each second on High (other tiers keep the one drawn during preparation) from a copy of its sky that shows only the aurora, at the size it was prepared with, since that size keys every lit program.

Nyra's close-up lighting (`close-up.js`) lives in her own materials: a soft key, a rim, a self-shadow from a depth map of her body along the world's sun, and the sea's caustics, all driven by uniforms. `app.lighting.closeUp(true | false | null)` forces it on or off, or returns it to the shots. A cinematic object may set `closeUp`, a boolean or a function evaluated each frame; without one, the lighting rises while a shot holds the camera within 3 m of her head. The self-shadow map renders through a scene of its own, so it never touches the world scene's light state.

## Character animation

`Input.running` begins false on new games and chapter restarts. Shift, R3 or the touch pace badge toggles it on a press edge; stops, menus and ordinary world crossings preserve it. Light touch-stick movement and LT retain a temporary careful-walk override. `Equipment.syncOrb` enables selection only when the active world's physical relay is ready. A prefetched neighbor cannot unlock it, and selecting a locked slot cannot interrupt reload. Automatic stowing remembers an equipped orb for restoration; an explicit pistol choice clears that pending restoration.

Rope swings and the free swing of their ropes advance on a fixed 1/240 s step (`ROPE_STEP`), with the stick, pump and steer applied inside each step, so a catch swings the same arc at any frame rate. Currents add the water's velocity to the swimmer's target in `Hero.swim` through the swim volume's `current(time, pos, feet)`; they act only in water.

`hero-anim.js` preserves the public `HeroAnimator`, `Spring`, `LIP` and `placeholderHero` exports. `animation/animator.js` owns transitions and update order; locomotion, traversal poses, overlays, feet, hands, face and secondary motion live in separate modules. Running recovery, body rise and carried arms follow actual displacement. The current lab uses the controller's exported `RUN_SPEED`; archived previews retain their original speed. Foot contacts, aiming, traversal and saved progress remain independent of background preparation.

`wall-climb.js` adds the `wall` state to `Hero` through one check before the state dispatch. Climbable surfaces are vertical rectangles kept in `world.walls`, each with a normal, extents, a kind (`ice` needs Mira's axes, `vine` needs bare hands) and whether its top can be mounted. Jump catches a surface in front from the ground, and a fall or jump catches one in reach. On it the body moves up, down and across at the kind's pace, Jump leaps to the farthest hold within reach along the stick (back and Jump kicks off), drop lets go, and reaching a mountable top hands over to the ledge climb. The four holds are planted in turn on a cycle driven by distance, and any hold leaving its shoulder's or hip's reach is replanted; a hand's landing is a strike (`axe` or `vine` hero events, `hero.wallStrikes` for chips and leaves). `animation/wall.js` turns those holds into arm and leg IK goals, and keeps Mira's axes on the pack or in the fists; they join the explorer's model in the animator's constructor, so every world's shader preparation includes them. `ice-axes.js` derives ownership from the session's pickup or a save that has reached the forest.

`animation/reload.js` opens both arms, ejects the empty magazines together and guides both actual magazine seats onto their belt replacements. Each pistol remains in its own hand throughout the 2.65 s exchange. Belt attachments follow the animated hips; IK preserves their contact through movement and turning. R reloads pistols; with the orb equipped, R retains its link action. `PISTOL_CAPACITY` supplies thirty-two combined rounds (sixteen per pistol) to the game and lab. Ammunition refills only on completion. Switching equipment or entering traversal cancels it and restores fitted parts without granting ammunition.

`equipment-sound.js` loads the shot, five isolated reload clips and three ledge traversal clips from local Atlas outputs. Release, belt pickup, seating and slide release follow reload events; magazine impact follows the first actual floor collision. Stereo placement distinguishes the hands. Procedural buffers preserve each event when loading or decoding fails, and the existing effects and master gains control both sources. Finished voices disconnect their nodes. Dropped magazines share source geometry and materials, expire after 6 s and stay bounded to 12 instances. Their actual lowest vertex supports landing, sloped rest and shrinking fade against world ray or ground queries. Traversal grip follows the ledge catch, while pull and boot seating follow normalized climb progress. Footstep sound follows the rendered stride for both walking and running.

The camera updates before equipment targeting and animation. Camera sight selects a physical ray endpoint; each barrel converges toward that endpoint and fires its own obstruction-aware ray. Pistol shots preserve centered hits and off-center misses. Orb links retain their aim cone. The reticle shows alignment, nearby barrel obstruction, confirmed hits and reload progress.

## Story scenes and voice

`mira-scenes.js` holds Mira's script (`MIRA_LINES`, each line's text, recording colour and clip length) and one scene per crossing: her field radio by the checkpoint's arrival path, her camp on the isles, her sign cut into the ice at the frozen lake's shore and the castle's address in the Wildwood. A controller builds its scene in `build`, calls its `update` every frame and its `reset` with the world, so each scene plays once per expedition and again after a chapter restart. A scene starts only in play, outside any other cinematic, crossing or knockout; it is a `Beat`, a `Shot` whose lines go through the voice, published as `beat` in the telemetry, and Enter or jump skips it. The reunion in space belongs to `starward.js`: Mira's light meets Nyra's and her live lines play before the continuation card and the completion callback.

`voice.js` gives every line one gain under `sound.master`, scaled by the `voice` setting, and its subtitle with a `Mira` speaker label. Recordings pass through a field radio or tape colour; live lines stay clear. `sound.voiceActive` is true only while a clip is heard. A scene calls `voice.alive()` each frame: when its frames stop (pause, notes, hidden tab) its lines pause and later resume with their subtitle. A clip that fails to load keeps its subtitle and a short procedural chirp.

## Sound

`sound.js` owns the mix. Effects (`sound.fx`) and the ambience bus meet in a diegetic bus that the water filter closes over as Nyra's head goes under; music runs through its own gentler muffle. Both pass a door membrane filter into `sound.mix`, which carries the master volume and a fixed loudness makeup into the limiter; a soft ceiling (`sound.output`) rounds off the limiter's brief overshoots. Voices from other modules connect to `sound.master` (master volume and its own trim, no membrane) and set `sound.voiceActive` while a line plays, which ducks music and ambience. `bootstrap.js` binds the application with `sound.bind(app)`, opens the context suspended and resumes it at the first press anywhere, and every `Gate` registers itself through `sound.addGate`. `sound.setTitle(true)` plays the title cue and holds the ambience duck at zero, set outright while the context is still suspended so no air leaks at the resume; a start calls `setTitle(false)` and `duck(false)`, so the world's air fades back in and a pause's duck never outlives the pause menu. Each envelope gain starts at `value = 0` before its first automation.

Each place's music layer adds stems from `music-stems.js`: a tension stem (drone, a percussion kit per place on a sixteenth grid, an ostinato) that follows danger, and a lift stem that answers discoveries with a sting in the place's key. `sound-scene.js` reads danger each frame from hostile `combatTargets()` within 40 m, an active boss and its phase, the air reserve and alert events; cinematics soften it and crossings clear it. `ambience.js` plays each place's beds, scattered one-shots and local sources (braziers, the spore bog, frozen falls, sea vents, open doors) panned from the camera and attenuated from Nyra. `body-sound.js` derives breathing, efforts, the surfacing gasp and low air strain from hero state transitions; breathing is heard only after about ten seconds of running and eases within a few seconds of stopping, softly and with the in-breath softer still; its recorded sprite falls back to a procedural voice. `action-sound.js` serves the traversal and combat verbs; `play` ignores unknown names. Sound modules import no three.js, so the receipt scripts render `sound.js` offline on a bare page.

At default settings the measured mix sits near -16 LUFS integrated with true peaks under -1 dBTP; `receipts/verification-sound-direction/scripts/` holds the offline renders, the per-world captures, the transitions and the node count check.

## Combat tuning and orb abilities

`combat-tuning.js` holds one table per `settings.difficulty` (story, standard, hard). Wardens, the castle keeper, boars and Oldtusk, the frost lynx, the Tide Guardian, `Breath` and the falling ice read it at each windup, hit or breath, so a change in the settings applies at once; Standard keeps the original timings. `composure.js` scales each hit and refills health pips one at a time after a quiet spell out of a fight (no hostile foe within 14 m, no active Tide Guardian, no checkpoint Warden on duty and, during the lynx hunt, only in the plateau notch), calling `sound.play("heal")`; refuges and knockouts still refill fully.

`Equipment.abilities` holds the orb's earned abilities. World controllers grant `pull` on the frost plateau and on entering the forest or the sea, and `shield` at the first forest seal and on entering the sea, so the chapter played implies them and saves keep no new key; each gets one control card per session. `RelayPull` turns a held link into a pull through the target's `pull({ phase })` and draws the tether fitted to every orb; `RelayShield` is fitted to the explorer and `Hero.takeHit` asks it to deflect. `pistol-craft.js` derives five pistol improvements from Mira's found relics.

## Asset finishing

`finishAsset` applies deterministic normal, roughness and subtle vertex color detail after factory loading in both runtime and lab. It preserves positions, native bounds, material colors, gameplay parts and shader hooks. Seamless maps are shared per substance and authored albedo, normal and roughness texture identities; each map's pixels depend only on its own source (albedo not even on the substance), so maps over equal source pixels share one `Source` and one upload. Finishing combines readable authored maps and preserves unreadable originals, shader hooks, UV transforms and mipmaps. The current hero cloth receives woven detail; skin boundaries remain independent. Anatomical skin, facial features, hair and transparent effects retain their original surfaces. The four archived explorer factories bypass finishing.

Early-world dressing runs during world construction before shader preparation. Ground cracks, paving wear, camp prints, snow stains and instanced fragments follow existing ground queries. All six worlds keep their original colliders, jump spans and puzzle anchors. Forest litter follows the actual surface height, and archive fragments avoid temporary bridges. Opening masonry uses fitted courses and beveled stone profiles inside the existing solid barriers; climbable caps retain flat support.

Local load failures retain the original error stack and stage on `window.__LOAD_ERROR__`. `scripts/serve.mjs` records loopback reports in `receipts/verification-loading-failure/live/errors.jsonl`. Diagnostic failure cannot replace the gameplay error or stop a successful load.

```sh
npm run check
node scripts/architecture-check.mjs
node scripts/save-check.mjs
node scripts/i18n-check.mjs
node scripts/animation-check.mjs --out outputs/animation
node scripts/playthrough.mjs outputs/playthrough

```

`scripts/architecture-check.mjs` holds the catalog, asset store, world manager, background work and module preload contracts above. Route scripts need the local server; `scripts/nightly.mjs` serves the checkout itself and adds the crossing measurement, the flash detector, shader compile tracking and fixed view comparisons ([runbook](nightly.md)). Scripts inside `receipts/` record the revision they tested and are not current checks. The [intermittent startup exception](../tasks/startup-box-error.md) remains a separate investigation.
